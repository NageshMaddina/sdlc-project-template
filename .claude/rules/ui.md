# UI rules

Source of truth: `design/` (tokens and screen specs) and `docs/design/` (the approved design spec for the story).

- Use components from `src/design/components/` first. A new shared component needs a line in the plan; one-off markup belongs in the screen.
- Colors, spacing, radii, type sizes and shadows come only from design tokens (`var(--…)` / the Tailwind theme generated from `design/tokens.json`). No raw hex, rgb, or pixel values that aren't on the scale. The lint hook rejects raw hex.
- Never edit `src/design/tokens.css` by hand; it is generated by `pnpm design:tokens` from `design/tokens.json`.
- Build every state the design spec lists: loading, empty, error, partial, success. A screen without its empty and error states is not done.
- Accessibility (WCAG 2.2 AA): real `<button>`, `<a href>`, `<label>` for inputs; visible focus; text contrast ≥ 4.5:1; status never shown by color alone; icon-only buttons have `aria-label`; everything works by keyboard.
- Copy comes from the design spec. Don't invent marketing text; leave `[COPY: …]` placeholders and list them in your summary.
- Each screen state in the spec gets a visual test in `tests/visual/`. Don't update baselines unless the user approved the design change.
